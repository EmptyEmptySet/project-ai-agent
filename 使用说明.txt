Mini Coding Agent 使用说明
============================

本说明介绍如何与编程智能体交互、最常用/最全面的功能，以及任务执行的工作区域（workdir）
如何设置。

一、如何提供凭据（二选一，绝不写入仓库）
1. 编辑本目录下的 config.json，把 xxx 替换为真实值：
   - base_url：OpenAI 兼容网关地址，如 https://api.openai.com/v1
   - model：模型名，如 gpt-4o-mini
   - api_key：你的 API key
   注意：config.json 已被 .gitignore 排除，不会入库；被排除的是一个“真实密钥”文件，
   如果你不小心写了真实 key，切记不要提交。
2. 或用环境变量（优先级高于 config.json）：
   Windows(PowerShell)：$env:AGENT_API_KEY="xxx"; $env:AGENT_BASE_URL="https://..."; $env:AGENT_MODEL="..."
   Linux/macOS：export AGENT_API_KEY=xxx AGENT_BASE_URL=... AGENT_MODEL=...

二、如何运行 / 交互方式
1. 安装依赖：pip install -r requirements.txt

2. 通过命令行传任务（一次性任务）：
   python main.py "列出当前目录结构，并写一个 hello.txt"
   可用参数：
     --offline            离线演示模式，不调用真实 HTTP 模型（用内置 MockLLM）
     --workdir <目录>      指定任务工作区域（默认取 config.json 的 workdir，缺省 ./workdir）
     --max-iterations N   覆盖配置里的最大轮数
     --json               以 JSON 输出结果（便于程序化调用/测试）
   --offline 适合没有密钥时验证流程；正式使用请去掉 --offline。

3. 通过标准输入传入任务（适合换行多行任务）：
   echo "你的任务" | python main.py
   或：type task.txt | python main.py

4. 交互式多次对话（进阶）：
   当前主程序为“单次任务”模型。若要连续完成任务，可在代码中多次调用：
     from agent_core import get_agent
     from agent_core.config import load_config
     agent = get_agent(load_config(workdir="."))
     print(agent.run("第一个任务"))
     print(agent.run("在此基础上继续做第二个任务"))
   说明：每次 agent.run 会新建对话历史；如需跨任务保留上下文，可在此基础上重用
   agent.memory，或保持同一 agent 实例并复用其历史（可自行扩展）。

三、特色 / 完整功能一览
1. 本地沙箱工具（全部在本机执行，不依赖云端）：
   - read_file   读取文件内容
   - write_file  写入/覆盖文件（自动创建父目录）
   - list_dir    列出目录子项
   - search_dir  按文件名/目录名关键字搜索
   - run_command 本地执行 shell 命令（含 stdout/stderr/退出码）
   所有路径都限制在 workdir 内，越界访问会被拒绝（安全防护）。
2. 完整自主闭环：上下文裁剪 + 工具执行 + 模型输出解析 + 终止判定 + 错误重试/退避。
3. 双层防上下文爆炸：单条工具输出截断 + 对话窗口裁剪。
4. 结果输出：默认人类可读，--json 可机器解析。
5. 超时与网络错误处理：模型调用失败自动重试至多 3 次。

四、任务执行的工作区域（workdir）在哪里 / 如何设置
工作区域（workdir）是 agent 读写文件、执行命令的“根目录 / 沙箱边界”；所有工具动作都被
限制在这个目录内，agent 无法访问其外部文件，越界会被拒绝。

本项目的默认工作区域是项目根目录下的 workdir 文件夹（DEFAULT_WORKDIR）。也就是说，你运行
python main.py 而不加任何参数时，agent 会在 ./workdir 内读写文件与执行命令，而不会在项目
根目录乱动。你可以先创建该目录并放入待处理的代码：mkdir workdir（本项目已预置）。

如何设置：
1. 默认（推荐）：python main.py "任务"
   —— 自动使用 config.json 里 workdir 字段指定的目录，缺省为 ./workdir。
2. 命令行临时指定：python main.py --workdir "J:/my_work" "任务"
   —— 适合把 agent 指向任意一个工程目录作为任务区，优先级最高。
3. config.json 中修改：把 "workdir": "workdir" 改成你想要的任务目录（如 "my_project"）。
4. 在代码中：get_agent(load_config(workdir_hint="你的目录"))。

建议：让 agent 只在你授权的任务目录（默认 ./workdir，或你在 config.json 指定的目录）里工作，
避免在生产/源码目录中被意外改动。

五、安全与注意事项
- 不要把真实 API key 写进代码、README、视频或提交到仓库。
- agent 会按你的提示执行命令，请在受控目录（workdir）内使用，避免误触危险命令。
- 工具输出的截断上限与对话窗口可在 config.json 中调整（max_tool_output_chars / max_history_messages）。

六、疑难排查
- 报错“未检测到 API key”：说明你仍处于在线模式但没提供 key，请填 config.json 或设置环境变量，
  或加 --offline。
- 在线调用 401/403：多为 api_key 或 base_url 填错，请核对网关地址与密钥。
- 想看清每一步：用 --json 查看 trace，掌握每轮调用了哪些工具。
