项目简介：Mini Coding Agent —— 简版编程智能体

一、这是什么项目
本项目是一个“简化的 Claude Code / Codex / OpenCode”式的编程智能体（coding agent）。
它通过与大语言模型交互，自主地在本地工作区读写文件、执行 shell 命令，从而完成用户交给的
编程任务。整个过程是一个 ReAct 风格的循环：
  用户任务 → 调用模型 → 解析输出（内容 + 工具调用）→ 本地执行工具 → 结果回填对话历史
  → 再次调用模型 …… 直到模型给出不含工具调用的最终答案，或达到最大迭代轮数。

二、项目如何满足题目要求
题目允许使用模型厂商 API 客户端、OpenAI 兼容网关及模型原生 tool calling；但不得使用任何
agent 框架 / SDK，也不得依赖服务端托管的代码执行或文件工具，且上下文管理、工具定义与执行、
模型输出解析、循环终止、错误处理必须自行编写。本项目全部满足：
1. 不使用任何 agent 框架 / SDK：纯 Python 手写循环与消息结构。
2. 工具全部本地执行：文件读写、列目录、搜索、shell 命令都在本机 workdir 沙箱内完成，
   并做路径越界防护，未借助 Code Interpreter / Files API。
3. 重要逻辑自主实现：
   · 对话历史与上下文管理 —— agent_core/memory.py（消息列表、token 估算、窗口裁剪）
   · 工具定义与本地执行 —— agent_core/tools.py（JSON Schema 声明 + 本地执行）
   · 模型输出解析 —— agent_core/llm.py（解析 chat/completions 的 content 与 tool_calls）
   · 循环终止条件 —— agent_core/agent.py（最终答案或最大迭代轮数判定）
   · 错误处理 —— 工具异常捕获回传、模型调用重试退避、参数校验、双层防上下文爆炸
4. 配置分层：API key 等凭据一律通过环境变量（AGENT_API_KEY / AGENT_BASE_URL / AGENT_MODEL）
   或未入库的 config.json 提供，且 .gitignore 已排除，保证不进仓库、不出现于 README / 视频中。

三、可运行性与代码质量
· 已通过模块编译检查（py_compile）。
· 已通过功能自检：完整闭环（列目录→读文件→写文件→最终答案）跑通并真实落盘；
  路径越界被拦截、shell 命令可执行、未知工具被友好报错、上下文裁剪与 system 保留均验证通过。
· 仅一个运行时依赖 requests，支持 Windows / Linux / macOS。

四、关于 API 与密钥的说明（重要）
受评审环境无法提供真实 API key 限制，本项目在验证时使用内置 MockLLM（offline 模式）演示循环，
未发起真实模型请求，也未使用任何密钥。真实可用的在线路径已完整实现于 agent_core/llm.py 的
OpenAICompatLLM，用户在提供 AGENT_API_KEY + AGENT_BASE_URL + AGENT_MODEL（或 config.json）
后即可直接切换到真实模型。此说明按任务约束记录于此，不对项目功能造成影响。

五、运行方式摘要
  pip install -r requirements.txt                     # 安装依赖
  export AGENT_API_KEY=你的key                        # 提供凭据（或写 config.json）
  python main.py "列出当前目录结构并写一个 hello.txt"  # 运行
  python main.py --offline "演示任务"                  # 无密钥的演示 / 测试
